# Multi-drive calibration investigation

Run `OPENBLAS_NUM_THREADS=1 nice -n 12 uv run calibration_survey.py` from the repository root while rendering. It samples the first frame of every segment with both forward sources, finds SIFT correspondences, rejects outliers with a homography, and fits relative rotation and wide focal length with robust angular loss. Every fifth route is held out wholesale for validation. Homographies and the ray fit favor dominant scenery and can still be biased by road-plane parallax, so inspect previews as well as residuals.

`calibration-scenes.json` contains manual half-resolution road and distant skyline traces for three paired wide/cabin frames. The solver pools the wide-camera reference and estimates cabin-to-wide rotation from paired horizon normals and road direction. Cabin validation leaves each scene out in turn. A skyline is only a proxy for level: terrain, roll/grade, and the approximate lens model can move it. The narrow overlap fit does not validate wide lens distortion at the edges.

`OPENBLAS_NUM_THREADS=1 uv run rear_window_survey.py` checks whether scenery tracked through the rear and both side windows supports a common cabin vanishing point on the side-window horizon. It filters for fast, low-rotation intervals using rlog camera odometry, rejects inconsistent optical flow, and reports independent window fits in `previews/rear-window-fit.json`. Rear glass is often overexposed or blocked; the glass edge, headrests, and luggage are not horizon observations. Disagreeing window fits are a reason to retain the current cabin calibration, not to average them blindly.

`OPENBLAS_NUM_THREADS=1 uv run landmark_alignment.py` tests direct wide-to-cabin matching over time: a landmark seen through the windshield may be seen a few seconds later through a cabin window. Only straight-motion intervals are sampled. Static correspondences should stay in the same plane around the travel direction, even as the bearing changes. The match coordinates are saved for visual review, and entire routes are held out. Repeated tree texture, moving vehicles, and incorrect matches can still fool the fit; passing vehicles are useful for visual seam checks but are not reliable static calibration landmarks. This experiment does not modify the active calibration.

`OPENBLAS_NUM_THREADS=1 uv run motion_alignment.py` tests motion-based rigid calibration instead of scene overlap. It uses rlog frame times to select corresponding time intervals, estimates rotation and translation independently from background features in each camera, then compares how well a single mount rotation explains both cameras on held-out drives. Turns help constrain rotation about the direction of travel. The result is diagnostic: planar scenes, moving foreground, camera lever arm, and the approximate lens model can bias the estimates. Results go to `previews/motion-fit.json`; no production settings are changed.

`uv run highway_survey.py --stride 4` ranks five-second highway windows by the 90th-percentile camera-odometry roll, pitch, and yaw rates. It saves the nearest calibrated road-relative attitude when present; this is not a per-frame gravity measurement. It exports capture-time-matched wide/cabin frames from distinct drives. `uv run highway_fit.py highway-scenes.json` fits road directions and distant horizons and validates by leaving one drive out. Annotations use 672×380 pixel coordinates. Use wall edges only when demonstrably parallel to the road, and do not use a wall or hill crest as the horizon. The fit is a candidate only and does not overwrite the active calibration.

`uv run segment_optimizer.py SEGMENT` runs a bounded gradient-based cabin yaw fit over all steady windows in one highway segment. It minimizes cross-camera angular motion-plane residuals with a robust loss and checks every third time block separately. Per-iteration yaw changes are limited to 0.25° and the total change to 4°; pitch and roll are locked so the horizon does not move. This is a geometric consistency objective, not a pixel seam loss: direct pixel RMS is only meaningful where both cameras see the same static surface. A candidate and per-window RMS report are saved to `previews/segment-optimizer/`; the batch is untouched.

`OPENBLAS_NUM_THREADS=1 uv run shared_lens_fit.py` fits independent three-axis rotations for wide and cabin while enforcing one shared focal length, principal point, and two radial coefficients. It uses the traced highways and `barrier-reference.json`, keeps the horizons in the objective rather than freezing pitch/roll, and holds out entire drives. Candidate and residuals are in `previews/shared-lens-fit/`. A parameter at its bound is a warning that the available traces do not independently constrain the lens fit. The transferred narrow rotation should be revalidated if adopting the candidate.

Outputs go to `previews/calibration-survey/`. The report requires at least 10 held-out forward segments and 25% improvement in both held-out forward and cabin median errors before recommending a visual review. The survey never changes live calibration or rerenders automatically. If the candidate passes and a multi-drive visual check confirms an improvement, render it into a new output directory so existing drives are not overwritten:

```sh
uv run stitch.py previews/calibration-survey/candidate.json --output videos-4k-refined --jobs 3 --resume
```
